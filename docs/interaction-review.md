# 全流程交互巡检

适用于 `1.0.0-dev`。自动验收通过不代替 Telegram 手机和桌面客户端体验，也不表示正式发布。

## 统一约定

- 主要操作突出，次要短按钮两列，长名称整行；数量调节、短金额预设和语言保留适合其含义的三列，不强制所有按钮同宽。
- 点击菜单通常原位更新；用户输入后的结果和纠错在输入下方发送，避免更新上方旧消息让人误以为没有响应。
- 格式错误与当前填写要求合为一条可继续回复的提示，更新绑定；旧回复/按钮不能消费新的输入。资金结果不明不自动重试。
- 返回保留已有上下文（如订单筛选、页码或购买数量）；取消填写不等于取消订单、撤销支付或撤回提现。未决保护不能通过菜单清除。
- 状态提示区分创建、付款、交付、申请审核与真实打款；管理员摘要不冒充买家交易回执。系统提示覆盖简中、繁中、英语，商家配置不擅自翻译。

## 检查范围

| 流程 | 交互与保护 | 自动验证 |
| --- | --- | --- |
| 首页、帮助、语言、公告 | 主入口、直达、当前语言、主动订退、历史公告不覆盖 | 首页/工具布局单测、UtilityNavigation |
| 分类、商品、数量 | 编号映射、长规格、售罄反馈、批量直输、明确返回对象 | 商品布局/数量单测、BulkQuantity |
| 资料、优惠码、确认 | 选择两列、单条纠错、资料保留、明确确认才建单 | Interaction/表单/优惠码单测、ReleaseJourney |
| 待支付、支付、取消 | 原支付复用、金额/超时明确、取消独立确认、不自动付费 | PendingOrder、ReleaseJourney 与竞态单测 |
| 钱包、充值、礼品卡 | 预设/费用、错误可回复、返回钱包、未知结果不盲重试 | 充值/礼品卡/Interaction 单测、EndToEnd、ReleaseJourney |
| 订单、查找、售后 | 结果下发、精确状态、来源页码、订单号客服草稿 | OrderNavigation、OrderSupport 与单测 |
| 自动/人工交付、TXT | 支付不冒充交付、本人领取、文件完整、防重复/未知发送 | AutoDelivery、BulkDeliveryTXT、CallbackRestart |
| 推广、提现 | 记录直达、单条纠错、二次确认、退出不解除保护 | AffiliateWithdrawal 与三语言/竞态/Redis 单测 |

真实协议验证运行固定官方商店、真实 Bot 与 Redis，Telegram 和支付为隔离模拟端点；两种数据库各执行完整 11 项旅程。入口为 `make verify`、`make telegram-e2e`；CI 另验证三版本升级、持久化、候选包及有界负载，见[整体验收](acceptance-v1.0.md)。

## 真人复测重点

1. `/start` 开始，直输大数量，故意填错资料/优惠码；直接回复最新纠错消息继续，检查不会漏看上方变化。
2. 在钱包自定义充值输入无效金额，再回复最新提示输入有效金额；`/back` 回预设，`/cancel` 回钱包，不应创建充值单。
3. 从非首页码/非全部状态查订单号，详情应在输入下方出现；返回保留来源。查找错误可直接退出或继续输入。
4. 提现填错金额或收款信息后回复最新提示，确认前不产生申请；退出只清草稿，不取消已有申请。
5. 用模拟渠道付款，分别核对付款通知、交付通知、TXT 和带订单号客服入口；不要把管理员创建通知当作付款或发货。

真人测试仅使用已授权的本地模拟沙箱，不扫码或转入真实资金。旧历史消息不会自动重写，请从新菜单开始。
